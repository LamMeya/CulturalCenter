# 斗门文化中心场地预约系统 — 需求文档

> 版本 1.0 | 2026-08-24

---

## 一、项目背景

珠海斗门文化中心下辖多个文化场馆（多功能舞蹈室、排练厅、书画室等），面向辖区内的文艺团体（舞蹈团、合唱团、书画社等）提供场地预约服务。由于热门时段供不应求，需建立一套公平、透明的预约抽签系统，避免先到先得的不公。

---

## 二、用户角色

| 角色 | 描述 | 使用端 |
|------|------|--------|
| 市民 / 文艺团体成员 | 浏览场馆、加入团队、预约时段、查看结果 | 小程序、iOS |
| 团队队长 | 管理团队（设置副队长/转让/解散）、查看预约统计 | 小程序、iOS |
| 场馆运营管理员 | 管理场馆、时间段、抽签分配、发布通知 | Web 管理后台 |
| 超级管理员 | 全部管理权限 + 管理后台用户管理 | Web 管理后台 |

## 三、功能需求清单

### 3.1 用户端（P0 核心）

#### F001 用户注册与登录
- 支持手机号 + 密码注册/登录
- 支持微信一键登录（小程序 code2session、iOS OAuth）
- 登录后持久化 token，7 天有效
- 未登录时仅可浏览场馆，不可预约

#### F002 首页浏览
- 品牌展示区：青绿渐变背景 + 三层波浪动画 + 文化中心名称
- 通知横幅：横向滚动展示公告（title + content 双行）
- 场馆列表：卡片式展示，含场馆名称、图片、容量、设施标签
- 点击场馆卡片跳转详情页

#### F003 场馆详情与预约
- 场馆头图：渐变背景 + 设施标签（空调/WiFi/镜子/音响等）
- 日期选择：14 天横向滚动，自动排除周一（闭馆日）
- 时段选择：上午/下午分组，多选（最多 4 个），选中态浅绿色
- 已选时段摘要：底部水平滚动展示
- 确认预约：底部悬浮按钮，提交后显示结果

#### F004 团队管理
- 无团队状态：空状态页 + 波浪装饰 + 创建/加入入口
- 创建团队：底部弹窗 Sheet，输入名称 + 简介
- 加入团队：底部弹窗 Sheet，默认显示全部团队列表，支持搜索
- 团队信息：名称/简介/人数/预约统计（近2周成功、近30天取消）
- 成员列表：队长/副队长/成员角色标识，点击展开/收起
- 队长管理：设置副队长（最多 4 名）、转让队长、解散团队
- 成员操作：退出团队

#### F005 我的预约
- 预约卡片列表：场馆名、团队名、预约人、日期、时间、状态标签
- 状态标签：待抽签（金色）、已中签（绿色）、未中签（灰色）、已取消（红色）
- 取消预约：仅本人预约 + pending/won 状态 + 未到期时显示按钮

#### F006 个人中心
- 用户信息展示：头像、昵称、手机号、所属团队
- 退出登录

#### F007 文化中心介绍
- 静态页面：预约规则、使用须知、联系方式

### 3.2 管理后台（P0 核心）

#### F008 管理员登录
- 用户名 + 密码登录
- 三级角色：超级管理员、管理员、操作员

#### F009 场地管理
- 场地 CRUD：名称、描述、容量、面积、设施、地址、图片上传
- 开关控制：is_open 控制是否对外展示

#### F010 时间段管理
- 批量生成：选择场馆 + 天数 + 上午/下午起止时间 + 时长
- 手动增删单个时间段
- 时间段状态：is_open、is_booked

#### F011 预约管理
- 预约列表：按状态筛选、按时间段分组
- 抽签操作：自动抽签、按时间段抽签、特权抽签（单个确认）
- 取消预约：管理员可取消任意预约

#### F012 通知管理
- 通知 CRUD：标题、内容、类型（normal/urgent）
- 发布/下架：控制是否在首页展示
- 已发布通知自动同步到小程序/iOS 首页

#### F013 管理员管理
- 管理员 CRUD：用户名、姓名、角色
- 启用/禁用

#### F014 App 用户管理
- 查看注册用户列表
- 查看用户所属团队、预约记录

## 四、非功能需求

### 4.1 性能
- API 响应时间 < 500ms（P95）
- 小程序首页加载 < 2s
- 支持 100+ 并发预约

### 4.2 安全
- 密码 bcrypt 哈希存储
- JWT token 认证，7 天过期
- 敏感操作需二次确认（解散团队、取消预约）
- CORS 全开放（开发阶段）

### 4.3 可用性
- 所有可点击元素有 `:active` 反馈
- 错误信息展示具体原因，避免通用文案
- 加载中显示骨架屏/旋转动画
- 空状态有引导性文案和操作入口

### 4.4 兼容性
- 小程序：微信基础库 2.x+
- iOS：iOS 15+
- 管理后台：Chrome/Safari/Edge 最新版

## 五、业务规则

### 5.1 预约规则

| 编号 | 规则 | 说明 |
|------|------|------|
| R01 | 必须以团队为单位预约 | 个人需先加入团队 |
| R02 | 每次最多选 4 个时段 | 上午/下午分开计算 |
| R03 | 预约后进入待抽签状态 | 由管理员统一抽签 |
| R04 | 2 周内成功预约上限 2 次 | 按团队统计 |
| R05 | 30 天内取消上限 2 次 | 按团队统计 |
| R06 | 周一不可预约 | 闭馆日，前端自动排除 |
| R07 | 已过期时段不可选 | 仅显示今日及以后的时段 |

### 5.2 取消规则

| 编号 | 规则 |
|------|------|
| C01 | 仅本人可取消自己的预约 |
| C02 | 仅 pending 或 won 状态可取消 |
| C03 | 预约日期未到期才可取消 |
| C04 | 取消后释放时段（is_booked = false） |

### 5.3 团队规则

| 编号 | 规则 |
|------|------|
| T01 | 每团队上限 80 人 |
| T02 | 队长 1 人，创建时自动担任 |
| T03 | 副队长最多 4 名 |
| T04 | 队长不可直接退出，需先转让 |
| T05 | 解散团队不可撤销，清空所有成员和预约记录 |
| T06 | 同一用户不可重复加入同一团队 |
| T07 | 查询团队列表时，按 user_id 过滤，只返回用户已加入的团队 |
